# 有两种输入模式，而且 OGCRL 里就是靠配置切换的。

在 robot_gc.yaml 里有一个 observation 参数，注释已经写了可选值是 state、visual，代码里训练时会把它传给 robot_gc_dataset.py。这里的逻辑很直接：如果是 visual，就把 head_camera 图像转成 64×64 的图像观测；如果是 state，就直接用 state 向量作为观测。

所以你可以理解为：

visual 模式：输入图像观测，适合视觉策略。
state 模式：直接输入状态序列，适合状态策略。
不过要注意一点，当前这份代码里真正实现的分支只有 visual 和 state 两种，没有看到一个完整实现的 both 分支；虽然配置注释里写了 both，但实际转换函数只处理了这两种。训练入口在 robotworkspace.py 会把这个参数原样传进去，所以实际跑哪个模式，完全取决于命令行里怎么覆盖 observation。

# 目标
同一个目标在两种模态下的表示”。

在训练里，OGCRL 的 goal 是跟输入模态绑定的：如果你设的是 visual，batch['actor_goals'] 和 batch['value_goals'] 就来自图像观测；如果你设的是 state，它们就来自状态向量。这个逻辑在 robot_gc_dataset.py 里体现得很直接，goal 是从 observations 里采样出来的。

但在评估和保存 goal 的时候，代码会把两种信息都存进同一个 goal 文件里，也就是同时保存 state 和 head_camera。然后在 eval_multi_dp.py 里根据 args.observation 选择用状态 goal 还是图像 goal。

所以结论是：

训练时：goal 也分 visual / state，两者和 observation 模式一致。
保存时：同一个目标文件里通常同时包含 state 和 head_camera。
语义上：不是两种不同目标，而是同一目标的两种表示方式。
